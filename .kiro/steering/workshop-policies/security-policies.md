# นโยบายความมั่นคงปลอดภัยของซอฟต์แวร์ (Security Policies)

ข้อกำหนดกลาง (Common Requirements) ด้านความมั่นคงปลอดภัยสำหรับการพัฒนาซอฟต์แวร์ทุกโครงการ ทีมพัฒนาต้องยึดถือและปฏิบัติตามตลอดวงจรการพัฒนา โดยออกแบบระบบตามหลักการคำนึงถึงความปลอดภัยตั้งแต่เริ่มต้น (Security by Design)

- ระบบต้องปฏิบัติตามแนวทางการป้องกันช่องโหว่ตามมาตรฐาน OWASP Top 10
- ห้ามฝังข้อมูลลับไว้ในซอร์สโค้ดโดยเด็ดขาด เช่น API Key รหัสผ่าน โทเคน หรือกุญแจเข้ารหัส และต้องบริหารจัดการผ่าน Environment Variables หรือเครื่องมือจัดเก็บความลับที่ปลอดภัย
- ต้องกำหนดสิทธิ์การเข้าถึงตามหลักการให้สิทธิ์เท่าที่จำเป็น (Least Privilege) และตรวจสอบสิทธิ์ในทุกคำขอที่เข้าถึงทรัพยากรที่ต้องได้รับการคุ้มครอง
- ต้องตรวจสอบและกลั่นกรองข้อมูลนำเข้าทั้งหมด (Input Validation) เพื่อป้องกันช่องโหว่ที่พบบ่อย เช่น Injection, XSS และ CSRF
- ข้อมูลอ่อนไหวและข้อมูลรับรองตัวตนต้องได้รับการเข้ารหัสทั้งในขณะจัดเก็บ (At Rest) และขณะรับส่งผ่านเครือข่าย (In Transit) ด้วยโปรโตคอลที่ปลอดภัย
- ต้องจัดการข้อผิดพลาดอย่างปลอดภัย โดยไม่เปิดเผยรายละเอียดทางเทคนิคภายใน และไม่บันทึกข้อมูลลับลงในบันทึกการทำงาน (Log)
- บริการหรือ API ที่เปิดให้เข้าถึงผ่านเครือข่ายต้องมีการพิสูจน์ตัวตนและการควบคุมการเข้าถึงที่เหมาะสม และรับเฉพาะข้อมูลที่จำเป็นต่อการทำงาน
